# Project audit — 10 October 2026

## Scope

Reviewed the static storefront and marketing build, catalog integrity, navigation and generated links, cart and WhatsApp handoff, search/pagination, image recovery, SEO output, dependency advisories, and local Supabase policy/import code. Live Supabase data and deployed Cloudflare configuration were not changed or verified.

## Findings and fixes

- **Cart crashes and invalid totals:** the cart page trusted parsed localStorage values, while the header used a different validator and wrote storage during initialization. Objects, null entries, invalid quantities, and storage exceptions could break the UI. Both now share typed validation; invalid records are discarded, duplicate slugs merge, failed writes are reported, and initialization does not write. Storage events refresh other tabs. Empty checkout now uses a valid `aria-disabled` value.
- **Missing image recovery after dynamic insertion:** image handlers attached only to initial DOM nodes, excluding cards cloned by search and pagination. A capture listener now handles image failures on dynamically inserted cards, including failure of the representative image itself.
- **Broken category navigation:** menus linked to `/category/tablets/detachable` even though no matching products existed and no static page was generated. Menu filters now use the same catalog matching rule as generated routes. The build verifier checks local link and asset targets across both sites.
- **Inconsistent storefront origin:** Astro's storefront configuration used the marketing apex domain. It now uses `https://shop.mobdeals.co.ke`, matching the storefront SEO configuration; marketing retains its own apex configuration.
- **Dependency advisories:** the initial npm audit reported 10 affected dependencies (7 high, 3 moderate). Applied compatible lockfile updates with `npm audit fix --package-lock-only --ignore-scripts`; the updated lockfile reports zero vulnerabilities. No forced major upgrades were used.
- **Check hint:** explicitly marked the third-party advertising script as inline to match its existing execution behavior.

## Verification

Final checks on the patched dependencies: `npm test`, `npm run check`, `npm run check:marketing`, `npm run lint`, `npm run build`, and `npm run build:marketing` passed. Both Astro checks report zero errors, warnings, and hints. Installation reports zero dependency vulnerabilities.

- Catalog inspection: 346 records; unique IDs/slugs, valid category references, nonnegative finite KES prices, and no active description markup detected by the inspected checks. Python automation scripts parse successfully.
- Regression coverage: malformed cart JSON/data, invalid quantities/prices, duplicate slugs, blocked storage, failed writes, persistence, and badge updates. Run with `npm test`.
- Browser smoke test: shop pagination; add, increment, decrement and remove cart items; WhatsApp order payload; malformed/blocked storage; search and pagination; dynamically inserted image fallback and failed fallback; mobile menu/Escape and homepage overflow at 390px. No JavaScript page errors observed. External requests were blocked so these tests isolate local behavior.
- Site verifier: 407 storefront pages and 2 marketing pages; local targets/media, canonical origins, sitemaps, unique product titles, empty filter pages, structured data, and absence of privileged credentials in generated output.

## Follow-up observations

The search and shop HTML are approximately 1.5 MiB and 1.4 MiB before transfer compression because they embed the full catalog in card templates. This is a performance opportunity for a separate pagination/data-loading change; this audit did not measure production Core Web Vitals. Remote product image availability, third-party services, and live database permissions require separate live checks.
